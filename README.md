# Starfall Vector

A tilt-controlled **3D space shooter for Android**, rendered with **Three.js / WebGL**,
wrapped as a native APK with **Capacitor**, and built end-to-end by **GitHub Actions**.

- Fully procedural visuals (no model/texture assets) — the whole game is ~160 KB gzipped.
- Deterministic fixed-timestep simulation (120 Hz) behind a variable-rate renderer.
- **Gyroscope/accelerometer steering** with calibration, iOS permission handling, and an
  automatic **touch-drag fallback** when no motion sensor is available.
- Synthesised audio (Web Audio API) — zero audio files in the APK.
- Native Android integration: immersive fullscreen, keep-screen-on, portrait lock,
  adaptive/monochrome launcher icons, splash screens, haptics hooks.
- CI that typechecks, lints, unit-tests (130 tests), builds, smoke-tests the game in a
  headless browser, and publishes an installable `.apk` on every release tag.

---

## Play it right now

The game runs in any WebGL-capable browser:

```bash
npm install
npm run dev        # dev server with HMR
# or
npm run build && npm run preview
```

On desktop: **arrows / WASD** steer, **space** fires, **P / Esc** pauses.
On a phone: tilt to steer (or drag anywhere with TOUCH mode), autofire is on by default.

## Android build

### In Android Studio (no signing needed for debug)

```bash
npm install
npm run android:apk      # build + cap sync + ./gradlew assembleDebug
# then:  adb install android/app/build/outputs/apk/debug/app-debug.apk
```

### Signed release build

1. Create a keystore (see `android/keystore.properties.example`).
2. Copy the example to `android/keystore.properties` and point it at your keystore
   (or export `SF_STORE_FILE / SF_STORE_PASSWORD / SF_KEY_ALIAS / SF_KEY_PASSWORD`).
3. `cd android && ./gradlew assembleRelease`

Without a keystore, `assembleRelease` still produces an APK — unsigned, which
`adb install` accepts after `apksigner sign --ks …` if you prefer to sign later.

### GitHub Actions (canonical pipeline)

The `.github/workflows/android-apk.yml` workflow builds **debug + release APKs**
on every `v*.*.*` tag or via `gh workflow run android-apk.yml`, and attaches the
APKs to the GitHub Release. Give it signing secrets and release builds are signed
on CI; otherwise the debug APK (already signed with the Android debug key) is
directly installable.

## Project layout

```
src/
  core/       deterministic building blocks: config, math, rng, pools, storage, types
  entities/   player, enemies, bullets, pickups (pure data + movement, no Three.js)
  systems/    difficulty curve, spawning/formations, collision, scoring
  fx/         particle & ring fields, camera shake
  input/      tilt steering (permissions, calibration, orientation remap) + touch steer
  audio/      zero-asset synth engine (sfx + sequenced music)
  ui/         DOM HUD / menus / calibration screen
  renderer.ts Three.js scene: procedural ship & enemy meshes, nebula, bloom, pooling
  game.ts     fixed-timestep game loop tying simulation + presentation together
  main.ts     boot, UI wiring, Capacitor bridge
android/      generated by Capacitor, customised (fullscreen, sensors, signing)
mobile/       icon/splash generation script + Play Store artwork
tests/        vitest unit suites + a Playwright headless-browser smoke test
.github/      CI + Android APK release pipeline
```

## Architecture notes

- **Simulation / presentation split.** `Game` steps logic in fixed `1/120 s` slices;
  `Renderer` reads the resulting state and draws once per frame. The gameplay layer
  never imports Three.js, which is why it unit-tests in Node.
- **Determinism.** Spawns, drops, weaves and shake all draw from a seeded Mulberry32,
  so a run seed (shown on the game-over screen) fully describes the run.
- **No per-frame allocation in hot paths.** Bullets, enemies, pickups and particles are
  pooled; particle state lives in flat `Float32Array`s; collision sweeps are index loops.
- **Tilt realism.** `TiltInput` handles the iOS 13 permission gate, portrait/landscape
  axis remapping, a sampled neutral baseline, deadzones, and sensor-null fallbacks;
  when the sensor never attaches (desktop, locked-down WebViews, cross-origin iframes
  without the gyroscope Permissions-Policy) the game transparently switches to touch
  drag and says so in the HUD mode chip.
- **Low-power path.** Core count + DPR decide whether UnrealBloom is enabled and how
  many particles/px get spent; bloom can be toggled from the menu too.

## Scripts

| command | what it does |
| --- | --- |
| `npm run dev` | Vite dev server (HMR) |
| `npm run build` | typecheck + production bundle |
| `npm test` | unit tests (vitest) |
| `npm run test:smoke` | headless-Chromium smoke test of the built game |
| `npm run lint` | eslint over src + tests |
| `npm run android:apk` | build + sync + debug APK |
| `npm run assets:generate` | regenerate launcher icons/splash from `public/icon.svg` |

- Node 22+, npm 10+
